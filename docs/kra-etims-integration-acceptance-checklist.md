# KRA eTIMS integration acceptance checklist

This checklist tracks external evidence required before production fiscalization can be considered. It is grounded in the [official contract gap analysis](kra-etims-official-contract-gap-analysis.md), [reconciliation contract status](etims-reconciliation-contract-status.md), [implementation inventory](implementation-inventory.md), [fiscal mapping configuration](fiscal-mapping-configuration.md), and [operations and deployment guide](operations-and-deployment.md).

**Status meanings:** **verified** means the narrow fact stated is supported by the cited current repository or official document; it does not mean production approval. **unverified** means external confirmation/evidence is still needed. **blocked** means the required evidence is a prerequisite to enabling the affected capability. Existing runtime gates remain closed.

## Readiness rule

Every item marked **blocked** must be closed with the evidence listed before the relevant capability can be considered for activation. A “verified” repository fact is not external approval. Unknown submission outcomes must remain unknown; neither an empty lookup nor a network timeout permits automatic resubmission under the currently reviewed contract. This checklist does not authorize changing runtime gates.
